# Корпус статей поддержки

Здесь должны храниться только одобренные статьи, которые можно использовать для ответов клиентам. В репозитории корпуса пока нет: BANKING77 содержит тексты обращений и метки намерений, но не ответы службы поддержки.

## Формат

Создайте `articles.jsonl`: один JSON-объект на строку, UTF-8. Нужны поля `id`, `title`, `content`, `source`, `updated_at`, `language`.

`id` должен быть стабильным и уникальным. `source` должен позволять оператору открыть первоисточник. `updated_at` фиксирует дату актуальности. `language` использует код вроде `en` или `ru`. В `content` помещается текст статьи после проверки владельцем базы знаний.

Не добавляйте пароли, персональные данные клиентов, внутренние заметки, закрытые инструкции или материалы без подтверждённого права использования. Сохраняйте лицензию и владельца документа.

## Первый retrieval baseline

`src/rag/retriever.py` проверяет JSONL, разбивает документы на фрагменты до 900 символов с перекрытием 120 символов и ищет по word TF-IDF unigram/bigram. `lexical_similarity` — сырой cosine similarity, не вероятность ответа. Порог релевантности не задан: его нужно определить на отдельном наборе запросов и размеченных релевантных статей.

Для оценки поиска подготовьте отдельный `queries.jsonl` с полями `query` и `relevant_document_ids`. Сначала измерьте Recall@5 и MRR на этих запросах, затем решите, нужны ли символьные признаки, BM25 или эмбеддинги. Не оценивайте retrieval только по примерам из корпуса.
