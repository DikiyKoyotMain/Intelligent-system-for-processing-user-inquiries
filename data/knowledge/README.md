# Корпус статей поддержки

Здесь должны храниться только одобренные статьи, которые можно использовать для ответов клиентам. В репозитории корпуса пока нет: BANKING77 содержит тексты обращений и метки намерений, но не ответы службы поддержки.

## Формат

Создайте `articles.jsonl`: один JSON-объект на строку, UTF-8. Нужны поля `id`, `title`, `content`, `source`, `updated_at`, `language`.

`id` должен быть стабильным и уникальным. `source` должен позволять оператору открыть первоисточник. `updated_at` фиксирует дату актуальности. `language` использует код вроде `en` или `ru`. В `content` помещается текст статьи после проверки владельцем базы знаний.

Не добавляйте пароли, персональные данные клиентов, внутренние заметки, закрытые инструкции или материалы без подтверждённого права использования. Сохраняйте лицензию и владельца документа.

## Первый retrieval baseline

`src/rag/retriever.py` проверяет JSONL, разбивает документы на фрагменты до 900 символов с перекрытием 120 символов и ищет по word TF-IDF unigram/bigram. `lexical_similarity` — сырой cosine similarity, не вероятность ответа. Порог релевантности не задан: его нужно определить на отдельном наборе запросов и размеченных релевантных статей.

Для оценки поиска подготовьте отдельный `queries.jsonl` с полями `query` и `relevant_document_ids`. Каждая строка — один вручную составленный запрос; список содержит все ID статей, которые эксперты считают релевантными. Если статьи с ответом нет, укажите пустой список. Пример формата (ID нужно заменить на реальные):

```json
{"query":"How can I reverse a card payment?","relevant_document_ids":["card_payment_reversal"]}
{"query":"Can I change my shoe size?","relevant_document_ids":[]}
```

Положительные запросы участвуют в Recall@5 и MRR. Recall@5 для запроса — доля размеченных релевантных статей, найденных среди первых пяти уникальных документов; MRR — обратная позиция первого релевантного документа, усреднённая по положительным запросам. Запросы без ответа учитываются отдельно и не включаются в эти две метрики: для них нужно отдельно разрабатывать и оценивать порог отказа. Реализация находится в `src/rag/evaluation.py`, а просмотр результатов — в `notebooks/02_retrieval_exploration.ipynb`.

Сначала измерьте метрики на экспертных запросах, затем решите, нужны ли символьные признаки, BM25 или эмбеддинги. Сравнивайте варианты на одинаковой выборке и разметке. Не оценивайте retrieval только по примерам из корпуса.
